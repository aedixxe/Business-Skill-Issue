# Business Skill Issue

Актуальная версия — **v0.3.0**. [Скачать последнюю версию](https://github.com/aedixxe/Business-Skill-Issue/releases/latest/download/Business-Skill-Issue.zip).

В v0.3.0 добавлен отдельный контекст Vero: B2B SaaS и адаптивный веб. В существующие правила встроены уточнение проблемы, короткие пакеты вопросов, сохранение обязательных решений и проверка требований с позиции дизайнера. Номер установленной версии указан в `metadata.version` файла `SKILL.md`. Ранее установленную копию нужно обновить: публикация релиза сама по себе не заменяет локальные файлы.

Скилл для проверки входных материалов и разбора бизнес-логики. Выявляет пробелы и противоречия, уточняет решения, описывает сценарии и готовит требования для передачи в [Дизайн ТЗ](https://github.com/aedixxe/design-tz). Сохраняет источники, вопросы, ответы и версии в рабочих документах. Скилл сам по себе ничего не публикует.

Основной маршрут: проверка входа → процесс и логика → вопросы и решения → проверенные требования → постановка дизайнеру через design-tz. Неизвестные правила остаются явными; готовность оценивается для конкретной части задачи. Анализ доступен без design-tz, но для подготовки постановки по его формату нужен этот скилл.

## Тандем с «Дизайн ТЗ»

Два скилла выполняют одну задачу последовательно. **Business Skill Issue** проверяет материалы, разбирает логику и уточняет решения. Затем отдельный скилл **Дизайн ТЗ** пишет постановку дизайнеру: цель, изменения, условия, ошибки, примеры и проверки. Требования и ответы сохраняются общими для обоих этапов.

Чтобы пройти весь путь, достаточно запроса: «Проверь эти материалы, уточни недостающую логику и подготовь ТЗ дизайнеру через Дизайн ТЗ». После проверки агент применяет второй скилл в той же задаче; повторно переносить материалы вручную не нужно. Если при написании обнаружился пробел, он возвращается в анализ, а после ответа обновляется соответствующая часть постановки. Если нужен только разбор, можно остановиться на требованиях.

Проведение приёмки продукта, планирование и выполнение нейробилда исключены. Создание макетов и прототипов отложено; существующие макеты можно использовать как источники. Ожидаемые результаты сценариев остаются частью требований.

## Установка

**Через skill-installer.** Попросите Codex: «Установи скилл из `https://github.com/aedixxe/Business-Skill-Issue/tree/main/skills/business-skill-issue` через skill-installer». Для CLI можно запустить:

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo aedixxe/Business-Skill-Issue \
  --path skills/business-skill-issue
```

Скилл станет доступен в следующем сообщении Codex после установки.

**Из ZIP-релиза.** Скачайте [актуальный Business-Skill-Issue.zip](https://github.com/aedixxe/Business-Skill-Issue/releases/latest/download/Business-Skill-Issue.zip) из [последнего релиза](https://github.com/aedixxe/Business-Skill-Issue/releases/latest), распакуйте папку `business-skill-issue` в `~/.codex/skills/` (или `$CODEX_HOME/skills/`). Внутри неё должен лежать `SKILL.md`. Если папка уже существует, сначала сохраните свои изменения и обновите её вручную.

Для полного тандема также установите [актуальный design-tz.zip](https://github.com/aedixxe/design-tz/releases/latest/download/design-tz.zip). Две папки скиллов размещаются рядом, а не одна внутри другой.

## Быстрый старт

Напишите Codex: «Используй Business Skill Issue. Вот описание задачи: … Разбери запрос и составь вопросы к заказчику». Можно начать с вопроса «Business Skill Issue, что ты умеешь?» без файлов и выбрать нужный режим работы.

По ходу работы агент сохраняет требования, вопросы, ответы, версии и решения в рабочих документах проекта. Для небольшой задачи достаточно одного документа с текущей сводкой и историей решений.

## Разработка

Для упаковки релиза требуется Python 3.9+ из стандартной библиотеки. Для работы скилла в разговоре и обычных документах Python не требуется.

Релизный ZIP собирается из фиксированного списка публичных файлов; `dist/`, `.qa/`, тесты и любые локальные документы проекта в него не входят:

```bash
python3 build_release.py --version v0.3.0
```
