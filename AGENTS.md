# Business Skill Issue

This repository distributes the `business-skill-issue` skill.

## Scope

- Keep the first version small: one adaptable workflow, optional stages with reasons, and versioned evidence in working documents.
- Skill instructions live in `skills/business-skill-issue/`. Repository documentation and release tooling live outside the installable skill where appropriate.
- Use synthetic examples only. Never commit customer materials, project workspaces, credentials, private links, or machine-specific paths.
- Publishing this skill does not authorize publishing a user's project data.
- Keep instructions and release contents consistent. Run relevant validation before releasing.
- Preserve concurrent edits. Assign ownership when delegating work on shared files.

## User experience

- The display name is **Business Skill Issue**; the skill identifier is `business-skill-issue`.
- A capabilities question should receive a helpful description of supported work and ways to start, without creating project files.
- Check incoming materials before deriving requirements; preserve unknowns and trace business logic across scenarios, permissions, states, data, and outcomes.
- Prepare requirements for design-tz; keep content sufficiency, approval of a specific version, and sending distinct.
- Product acceptance and neurobuild planning/execution are out of scope. Creating mockups and prototypes is deferred. Preserve expected outcomes as part of requirements.
- Stage progress must reflect evidence, including partial answers, technical blockers, and changes after approval.
